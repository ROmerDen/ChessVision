# ChessVision — что доделать до работы «как задумано»

Документ составлен после просмотра архива `ChessVision.zip`. Он описывает разницу между текущим прототипом и целевой версией: приложение на Android, которое в учебной партии против бота распознаёт позицию на доске Chess.com, анализирует её локальным Stockfish и показывает три варианта стрелками поверх доски.

## Текущий статус

**Сейчас в архиве есть прототип этапа 1, но не готовое приложение.** Реализованы Kotlin-модуль UCI, структурная проверка FEN, минимальный Compose-интерфейс, поиск нативного файла движка, JVM-тесты и один instrumented-тест. В README прямо указано, что код не собирался и не запускался.

В архиве пока нет самого Stockfish-бинарника, Gradle Wrapper, захвата экрана, распознавания шахматной доски, истории ходов, наложения стрелок и интеграционного теста всего сценария.

# План работ

## Этап 0. Сделать сборку воспроизводимой

- [ ] Добавить Gradle Wrapper: `gradlew`, `gradlew.bat`, `gradle/wrapper/gradle-wrapper.jar`.
- [ ] Зафиксировать совместимые версии Android Gradle Plugin, Kotlin, Gradle и JDK в одном месте.
- [ ] Открыть проект в Android Studio и добиться успешного Gradle Sync.
- [ ] Выполнить `:app:testDebugUnitTest` и исправить все ошибки компиляции и тестов.
- [ ] Собрать пустой debug APK и установить его на Android-устройство.
- [ ] Проверить, что `applicationId`, `namespace`, тема и зависимости согласованы.
- [ ] Добавить CI-проверку сборки и JVM-тестов (не обязательно для личного использования, но полезно для защиты от регрессий).

**Готово, когда:** проект чисто собирается на другой машине по README, а не только в исходной среде разработчика.

## Этап 1. Довести Stockfish/UCI до надёжной работы на телефоне

### 1.1. Сборка движка

- [ ] Исправить `scripts/build_stockfish.sh`: перед компиляцией вызвать `make net`, чтобы скачать и встроить NNUE-сеть.
- [ ] Сверить команды кросс-компиляции с актуальной официальной инструкцией Stockfish. Сейчас скрипт использует собственный `CXX` и API 26; проверить выбранную версию NDK и совместимость с закреплённым тегом Stockfish.
- [ ] Проверить пути NDK для Linux и macOS; отдельно описать, что Windows/MSYS пока не поддерживается скриптом.
- [ ] После сборки проверить архитектуру файла (`file`), ELF-заголовки и выравнивание сегментов для устройств с размером страницы 16 КБ.
- [ ] Не класть случайный desktop-бинарник в `jniLibs`: нужен именно Android ARM64 executable.
- [ ] Добавить инструкцию, как повторить сборку с чистого checkout и как обновлять закреплённый тег.

Официальная инструкция Stockfish: https://official-stockfish.github.io/docs/stockfish-wiki/Compiling-from-source.html

### 1.2. Запуск и протокол

- [ ] Проверить реальный запуск `libstockfish.so` через `ProcessBuilder` на физическом ARM64-телефоне. Сам факт упаковки файла в `jniLibs` ещё не доказывает, что ОС разрешит его запустить.
- [ ] Проверить handshake `uci` → `uciok`, настройки `Threads`, `Hash`, `MultiPV`, `isready` → `readyok`.
- [ ] Проверить несколько последовательных `position fen` / `go` на одном процессе.
- [ ] Проверить `bestmove (none)` и `bestmove 0000` для позиций без легальных ходов.
- [ ] Проверить timeout, отмену корутины, `stop`, аварийное завершение процесса и повторный запуск движка.
- [ ] В `ProcessUciTransport.close()` корректно дождаться завершения процесса и при необходимости принудительно завершить его; проверить закрытие reader/channel без потери последней строки.
- [ ] В `UciEngine.start()` закрывать транспорт и сбрасывать состояние при любой ошибке handshake/инициализации, а не только при timeout.
- [ ] Проверить гонку в `AnalysisViewModel`: `finally` старой отменённой задачи не должен сбрасывать `busy` для новой задачи. Привязать обновление состояния к актуальному `Job` или использовать идентификатор запроса.
- [ ] Проверить, что отмена анализа не оставляет старые `info`-строки в очереди и не загрязняет следующий запрос.
- [ ] Добавить тесты на таймауты, отмену, обрыв процесса, ошибку старта, пустую PV, меньше трёх доступных линий и повторный анализ.
- [ ] Показывать в UI понятное состояние «движок запускается / анализирует / ошибка», а не только финальный текст.
- [ ] Добавить настройки времени анализа, числа потоков и Hash с безопасными ограничениями памяти/нагрева.

**Готово, когда:** на телефоне приложение стабильно принимает FEN, возвращает до трёх PV-линий с оценками и ходами, выдерживает серию анализов и корректно восстанавливается после ошибок.

## Этап 2. Сделать корректную шахматную модель партии

- [ ] Подключить шахматную библиотеку для разбора позиции, проверки легальности ходов и применения ходов.
- [ ] Создать `GameState` / `GameRepository`, который хранит начальную позицию и последовательность подтверждённых ходов.
- [ ] Строить FEN из истории, а не пытаться восстановить её только по картинке.
- [ ] Учитывать рокировку, взятие на проходе, превращение пешки, сторону хода, счётчик полуходов и номер полного хода.
- [ ] Сверять распознанное изменение доски с легальными ходами из текущей позиции.
- [ ] Если приложение запущено посреди партии, предусмотреть ручной ввод FEN или отдельный режим начальной настройки позиции. Не притворяться, что все поля FEN можно достоверно извлечь со скриншота.
- [ ] Добавить тестовые партии с рокировкой, en passant, превращением и взятиями.

**Готово, когда:** после каждой подтверждённой последовательности ходов модель строит правильную FEN, которую Stockfish принимает без ошибок.

## Этап 3. Захват экрана Android

- [ ] Добавить экран объяснения и явного согласия на захват экрана через `MediaProjection`.
- [ ] Реализовать foreground service с корректным типом `mediaProjection`, уведомлением и жизненным циклом для целевых версий Android.
- [ ] Обрабатывать отказ пользователя, остановку сессии, блокировку экрана, поворот устройства и уничтожение процесса.
- [ ] Получать кадры через `MediaProjection` / `VirtualDisplay` / `ImageReader`.
- [ ] Ограничить частоту обработки кадров (начать примерно с 1–3 кадров/с), не анализировать один и тот же кадр бесконечно.
- [ ] Не сохранять и не отправлять кадры в сеть: обработка должна оставаться локальной.
- [ ] Исключить overlay ChessVision из распознаваемого изображения или маскировать его, чтобы собственные стрелки не ломали распознавание.

**Готово, когда:** приложение с разрешения пользователя стабильно получает кадры Chess.com на реальном устройстве и корректно завершает захват.

## Этап 4. Распознавание доски и фигур

- [ ] Реализовать поиск границ шахматной доски и выделение области 8×8.
- [ ] Добавить ручную калибровку рамки доски как fallback для разных размеров экрана и тем оформления.
- [ ] Определять ориентацию доски (белые снизу / чёрные снизу).
- [ ] Реализовать классификацию фигур на клетках. Сначала можно использовать шаблоны/классификатор, затем при необходимости модель ML; OpenCV использовать для геометрии и предобработки.
- [ ] Учитывать анимации ходов, подсветку выбранных клеток, координаты, маркеры и эффекты Chess.com.
- [ ] Ввести confidence score для каждой клетки и всей позиции.
- [ ] Не передавать позицию в движок, если распознавание неуверенное или позиция нелегальна.
- [ ] Добавить стабилизацию: считать позицию изменившейся только после нескольких согласованных кадров и окончания анимации.
- [ ] Проверить распознавание на разных темах доски, наборах фигур, масштабе интерфейса и ориентации экрана.

**Готово, когда:** программа устойчиво распознаёт начальную позицию и обычные ходы, а при сомнении скрывает подсказки вместо показа ошибочных.

## Этап 5. Анализ изменений и три варианта

- [ ] Связать `BoardStateTracker` с `GameState`: новое распознанное состояние должно соответствовать одному легальному ходу или явно запрашивать ручную коррекцию.
- [ ] Запускать Stockfish только после подтверждённого изменения позиции, а не на каждом кадре.
- [ ] Отменять устаревший анализ, если позиция уже изменилась.
- [ ] Показывать три лучших варианта, если движок действительно вернул три линии; не выдумывать недостающие варианты.
- [ ] Согласовать систему координат UCI (например, `e2e4`) с координатами клеток на экране.
- [ ] Зафиксировать цвета стрелок: первый вариант — зелёный, второй — синий, третий — фиолетовый; сделать легенду и настройки видимости.
- [ ] Не называть второй и третий варианты «неточностью» и «зевком»: это просто альтернативные линии. Ошибка оценивается только после сравнения реально сыгранного хода с лучшим ходом в позиции до него.
- [ ] Для учебного разбора после хода отдельно сравнивать оценку до и после хода и классифицировать потерю оценки с понятными порогами.

**Готово, когда:** для каждой стабильной позиции на доске отображаются именно те три линии, которые вернул движок, с корректно направленными стрелками.

## Этап 6. Overlay со стрелками

- [ ] Добавить отдельный сервис overlay и запрос разрешения `SYSTEM_ALERT_WINDOW` с понятным объяснением.
- [ ] Использовать прозрачное окно `TYPE_APPLICATION_OVERLAY`, не перехватывающее касания и не мешающее управлять Chess.com.
- [ ] Преобразовывать координаты клеток доски в экранные координаты с учётом положения, размера и ориентации доски.
- [ ] Рисовать стрелки поверх доски с масштабируемой толщиной, наконечниками и цветами.
- [ ] Пересчитывать геометрию после поворота, изменения размера окна, системных панелей или масштаба интерфейса.
- [ ] Предусмотреть быстрое скрытие стрелок и полное выключение overlay.
- [ ] Проверить, что overlay не попадает в захватываемые кадры и не создаёт рекурсивные артефакты.

**Готово, когда:** стрелки совпадают с нужными клетками на реальном экране и не блокируют управление игрой.

## Этап 7. Полировка и сквозные испытания

- [ ] Проверить полный сценарий: запуск ChessVision → разрешение захвата → калибровка → старт партии против бота → распознавание хода → анализ → стрелки.
- [ ] Прогнать тесты на нескольких Android-версиях и размерах экрана.
- [ ] Измерить расход CPU, RAM, батареи и нагрев при длительной партии.
- [ ] Добавить ограничение Threads/Hash и паузу анализа при перегреве или низком заряде, если это необходимо.
- [ ] Добавить журнал диагностики без сохранения лишнего содержимого экрана.
- [ ] Сделать обработку всех разрешений понятной: MediaProjection и overlay — разные разрешения, пользователь должен иметь возможность отключить каждое.
- [ ] Проверить, что приложение используется в учебном режиме против ботов, как задумано проектом.
- [ ] Подготовить debug APK для личного тестирования; публикацию и распространение отложить до отдельного решения.

**Финальный критерий:** на физическом Android-телефоне ChessVision сопровождает учебную партию против бота, корректно распознаёт каждую позицию, анализирует её локальным Stockfish и показывает три правильные стрелки поверх доски без ручного ввода FEN.

# Приоритет ближайшей итерации

Не пытаться делать всё одновременно. Следующий рабочий спринт:

1. Добавить Gradle Wrapper и добиться успешной сборки проекта.
2. Исправить Stockfish build script (в первую очередь `make net`) и собрать Android ARM64-бинарник.
3. Запустить движок на реальном телефоне и пройти UCI instrumented-тест.
4. Исправить отмену/таймауты/закрытие процесса и гонку `busy` в ViewModel.
5. Только после этого переходить к шахматной модели партии и захвату экрана.

## Важные ограничения

- Текущий код в исходном ZIP не был собран или проверен на устройстве. Этот план не означает, что тесты уже прошли.
- Один скриншот не содержит всей информации, необходимой для полной FEN. Нужна история ходов или ручная начальная позиция.
- `MultiPV=3` означает три лучших альтернативных продолжения, а не три категории качества хода.
- Настройки `Threads`, `Hash` и времени анализа должны быть проверены на конкретном телефоне: слишком высокие значения могут вызывать нагрев и расход батареи.
